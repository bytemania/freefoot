## 2. Feasibility & Performance Verdict (JS / Node / Mobile)

**Baseline Budget:** `freefoot` runs at `20 Hz` ([`TickConfig.js`](../../src/engine/TickConfig.js#L9-L11), ~114k ticks/match) with a Node benchmark target of **`<= 0.33 ms / 20 ticks`** (CI ceiling `1.0 ms`, [`bench.js`](../../src/calibration/bench.js#L15-L16)). `calibrate.mjs` runs `4 cohorts × 200 matches = 800 matches` across `os.availableParallelism()` worker threads.

| Model | Per-Tick CPU Complexity | `calibrate.mjs` Impact | Determinism & Serialization Risks | Verdict |
| :--- | :--- | :--- | :--- | :--- |
| **1. Lightweight TTI + Static `xT`** | `decideCarrier()` runs at most once per 5 ticks (and pauses `settleTicks=90` / `settlePressureTicks=24` after reception → ~0.12 calls/tick avg). Evaluating 10–14 pass endpoints × 11 opponents × ~20 FLOPs ≈ **2.5k FLOPs/decision (~3 µs)**; `xT` is an `O(1)` `Float64Array` lookup. Amortized: **`< 0.008 ms / 20 ticks` (< 2.5% of budget)**. | Negligible (`+1–3%` wall time). | **Low.** Zero RNG draws required. Use deterministic `score > bestScore` over ascending `onPitchList` order, and use `detmath.js` `sigmoid` (avoiding platform-varying `Math.atan2`/`Math.pow`). | **High Feasibility (Go)** |
| **2. Buckland Support Spot Calculator** | Shared team-level sampling of **16–20 spots** every **`N = 10` ticks (0.5 s)** when in possession: `20 spots × 11 opponents × ~15 FLOPs ≈ 3.3k FLOPs / 10 ticks` = **~0.5 µs/tick (`< 0.01 ms / 20 ticks`)**. Actually *cheaper* than expanding per-player ring searches for 7 attackers every 5 ticks. | Negligible (`+1–2%` wall time). | **Medium (manageable).** Zero RNG draws, tie-break by spot index then player index. **Important:** any cached spot assignments or hysteresis state stored on `TeamState`/`PlayerMatchState` **must** be added to `MatchState.serialize()` / `restore()` ([`MatchState.js#L228-L388`](../../src/engine/state/MatchState.js#L228-L388)) so mid-match save/resume and `replay()` hashes stay identical. | **High Feasibility (Go)** |
| **3. Team Tactical Phase + Extended Profiler** | Updating a discrete `team.phase` enum once per 5 ticks is `O(1)` (`< 0.1 µs/tick`). Extended calibration metrics are aggregated once at full-time from `engine.getStats()` + `eventLog`. | Zero tick overhead; `< 1%` post-match aggregation. | **Low.** If `team.phase` includes a transition timer (e.g., 40 ticks / 2 s after turnover), serialize `{ phase, phaseTick }` on `TeamState`. | **Trivial Feasibility (Go)** |
| **4. Branching First Touch + Same-Seed A/B** | `reception()` + `looseBall()` execute only ~500–900 times per full match. Zero measurable tick impact (`< 0.001 ms / 20 ticks`). | Zero impact. | **Medium (RNG stream sensitivity).** Adding extra `state.rng` draws inside `reception()` shifts all downstream RNG on every seed. **Mitigation:** resolve Clean / Heavy / Spill from the **single existing `u` draw** against two thresholds (`u < pClean`, `u < pHeavy`), or derive heavy-touch scatter from a keyed substream like [`bodyRandom`](../../src/engine/rng/streams.js#L43-L45) so toggling the rule in A/B tests doesn't scramble unrelated draws. | **High Feasibility (Go)** |

## 3. Recommended Phase 2 Slice Order (Post-Slice 10)

Ordered for **highest ROI, lowest risk, and one-concern-per-PR isolation**:

### Slice 11 — Same-Seed A/B Diff CLI & Extended Cohort Profiler *(Tooling Foundation — Zero Gameplay Diff)*
- **Scope:**
  - Add a lightweight CLI helper (e.g., `scripts/ab-diff.mjs --seed 42 --override decision.w.pass.progress=1.2`) that runs baseline vs. overridden `config` (deep-cloned before `buildTickConfig()`) on the exact same seed, reporting first-divergence tick, event-log diff, and `getStats()` deltas.
  - Extend [`cohort-worker.js`](../../src/calibration/cohort-worker.js#L16-L26) and [`cohorts.js`](../../src/calibration/cohorts.js#L211-L315) to surface non-gating L2/L3 diagnostics already computed by `MatchStats` (`passes`, `passCompletionPct`, `progressivePasses`, `interceptions`, `miscontrols`, `shotsInBoxPct`, `fieldTiltPct`, `ppda`) plus top-3 outlier seeds per cohort for `#seed` inspection.
- **`config/weights.yaml` touched:** None.
- **Calibration metrics touched:** None (reporting only; golden seeds remain 100% unchanged).

### Slice 12 — Branching First Touch (Clean / Heavy Momentum Touch / Loose Spill)
- **Scope:**
  - Upgrade [`firstTouch`](../../src/engine/resolve/passing.js#L44-L48) to incorporate `composure` and incoming ball height/bounce, returning a 3-way outcome (`CLEAN`, `HEAVY`, `SPILL`) from a single `u` draw.
  - In [`contacts.js`](../../src/engine/resolve/contacts.js#L283-L361) (`reception`, `looseBall`): `CLEAN` keeps `giveBall()`; `HEAVY` completes the pass (`endPass(state, true)`) but knocks the ball `1.5–3.5 m` ahead along the receiver's velocity/attack vector via `launchGround()` (`b.owner = -1`) and sets `r.pendingAction = ACTION.CHASE` (allowing nearby pressers to pounce naturally); `SPILL` keeps existing `MISCONTROL` scatter.
- **`config/weights.yaml` touched:** `firstTouch.{t0..t4}`, plus new `firstTouch.{t5Composure, t6Height, heavyOffset, heavyKeepSpeed}`.
- **Calibration metrics touched:** `passCompletionPct`, `possessionPct`, `interceptions`, `tackles`, `shots`, `goals` (and new `miscontrols` diagnostic).

### Slice 13 — Kinematic Time-to-Intercept (TTI) Pass Probability + Static `xT` Grid
- **Scope:**
  - Add a pure, allocation-free `passInterceptMargin()` helper in [`Perception.js`](../../src/engine/decisions/Perception.js) that computes ball flight time `tBall` to the target point `(ax, ay)` (including projected lead point for `THROUGH` / `ACTION.RUN` teammates) vs. fastest opponent arrival time `tDef = tReact + dist(q + q.v * tReact, interceptPt) / (topSpeed * chaseFraction)` across the 11 opponents.
  - Add a static `12 × 8` `xT` `Float64Array` lookup table (`xT(along, y)`) and integrate both into [`CarrierDecision.js:passScore`](../../src/engine/decisions/CarrierDecision.js#L135-L153) and [`inspect.js:inspectCarrierDecision`](../../src/engine/debug/inspect.js#L72-L119).
- **`config/weights.yaml` touched:** `decision.w.pass.{laneSafety, progress, receiverFree}` + new `decision.w.pass.{tti, xt}` and `decision.tti.{reactionSec, marginScale}`.
- **Calibration metrics touched:** `passCompletionPct`, `progressivePasses`, `offsides`, `shots`, `shotsOnTarget`, `xG`, `shotsInBoxPct`, `goals`, and `moderate`/`heavy` strength-tier `favWin` & `favShotShare` (since `pace`, `vision`, and `passing` now interact kinematically).

### Slice 14 — Explicit Team Tactical Phase & Shared Support Spot Calculator (Buckland)
- **Scope:**
  - Add a compact `phase` state (`BUILD_UP`, `PROGRESSION`, `FINAL_THIRD`, `DEFEND`, `TRANSITION_ATT`, `TRANSITION_DEF`) to [`TeamState.js`](../../src/engine/state/TeamState.js) (serialized in `MatchState`), updated once every 5 ticks before [`computeAnchors`](../../src/engine/tactics/Formation.js#L204-L248) so `Formation.js` and `OffBallDecision.js` read one canonical phase.
  - Upgrade [`OffBallDecision.js:supportRun`](../../src/engine/decisions/OffBallDecision.js#L301-L334) to evaluate a shared **16–20 spot** fan/ring around the carrier in the attacking half every **10 ticks (0.5 s)**, scoring spots by `(1) lane safety to carrier`, `(2) optimal distance band (8–22 m)`, `(3) opponent clearance`, and `(4) xT`. Assign the top 1–2 spots to the nearest eligible off-ball teammates (`MF`/`W`/`ST`) with a hysteresis bonus (`hysteresis`) to eliminate target jitter.
- **`config/weights.yaml` touched:** `support.{ringRadius, points}` expanded to `support.{cadenceTicks, spotRadiusMin, spotRadiusMax, optPassDist, wLane, wDist, wSpace, wXt, hysteresis}`, plus `offBall.transitionTicks`.
- **Calibration metrics touched:** `passes`, `passCompletionPct`, `finalThirdPassPct`, `fieldTiltPct`, `distanceKm`, `sprints`, `shots`, `goals`.

## 4. What to Skip or Simplify

1. **Skip full-pitch continuous Pitch Control grids / Spearman PDE integrals:** Computing a `50 × 34` pitch-control surface every tick requires ~37,400 player-cell evaluations per tick (~20–40× slower) and will blow past the `0.33 ms / 20 ticks` budget on mobile WebViews and `calibrate.mjs`. Evaluating kinematic TTI **only at the 10–14 discrete pass candidate points** (plus 1 midpoint check for ground passes) captures ~90% of the passing realism at `< 3%` CPU cost.
2. **Skip Buckland's full-half 48–60 spot grid evaluated every tick:** A **16–20 spot** local fan/ring around the carrier updated every **10 ticks (0.5 s)** with hysteresis gives crisp passing triangles without oscillation or wasted evaluations in irrelevant corners of the pitch.
3. **Skip an `open-football`-style ECS / Behavior Tree rewrite:** `freefoot`'s flat `PlayerMatchState[]`, `onPitchList`, integer `ACTION` enum, and zero-allocation pure resolvers (`passing.js`, `duels.js`, `shooting.js`) are already ideal for V8 JIT and determinism. Borrow only the **explicit team tactical phase** and **match-result profiling diagnostics**.
4. **Skip custom multi-tick dribble-physics states for Heavy First Touch:** Keep the clean `b.owner` snap for controlled receptions. Model a heavy touch by reusing existing `launchGround()` (`b.owner = -1`) + `ACTION.CHASE` so `BallPhysics.js` and `contacts.js:looseBall()` handle interception, tackles, and out-of-play automatically with zero new physics branches.
5. **Skip dual side-by-side live canvas rendering in the first A/B iteration:** Start with the CLI same-seed diff (`scripts/ab-diff.mjs`) and, if visual A/B is needed later, add a single-canvas preset toggle or ghost-ball replay overlay inside the existing `#seed` viewer rather than doubling 60 FPS canvas draw calls on mobile.
